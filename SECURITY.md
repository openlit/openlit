# Security Policy

## Supported versions

Security fixes are made in the current releases of maintained OpenLIT
components. Upgrade to the latest applicable release before reporting a
problem when possible. Older releases may not receive fixes or backports.

## Reporting a vulnerability

Please do **not** open a public GitHub issue for a suspected vulnerability.

Report it privately by either:

1. Using GitHub's [private vulnerability reporting form](https://github.com/openlit/openlit/security/advisories/new), when it is available; or
2. Emailing [developers@openlit.io](mailto:developers@openlit.io) with the subject
   `OpenLIT security report`.

Include a clear description of the issue, affected components and versions,
steps to reproduce or a proof of concept, likely impact, and any suggested
mitigation. Do not include credentials, access tokens, production data, or
other unnecessary sensitive information.

Maintainers will acknowledge receipt, investigate privately, and coordinate a
fix and disclosure timeline with the reporter. Please give maintainers a
reasonable opportunity to investigate and release a fix before public
disclosure.
